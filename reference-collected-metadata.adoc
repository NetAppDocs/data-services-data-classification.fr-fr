= Métadonnées collectées à partir de sources de données dans la NetApp Data Classification
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Data Classification collecte des métadonnées lors de l'analyse de vos sources de données et de vos systèmes. Certains attributs de métadonnées ne sont pas disponibles pour tous les protocoles.

[cols="15,25,25,25"]
|===
|  | *Métadonnées* | *CIFS* | *NFS* 


.3+| *Horodatages* | _Heure de création_ | disponible | Non disponible (non pris en charge sous Linux) 


| _Dernière consultation_ | disponible | disponible 


| _Dernière heure de modification_ | disponible | disponible 


.2+| *Autorisations* | _Ouvrir les autorisations_ | Si le groupe « TOUT LE MONDE » a accès au fichier, il est considéré comme « Ouvert à l'organisation » | Si « Autres » a accès au fichier, il est considéré comme « Ouvert à l'organisation » 


| _Accès utilisateurs/groupes_ | Les informations sur les utilisateurs et les groupes sont extraites de LDAP | Non disponible (les utilisateurs NFS sont généralement gérés localement sur le serveur, par conséquent, le même individu peut avoir un UID différent sur chaque serveur) 
|===
[NOTE]
====
* La classification des données n'extrait pas la « dernière heure d'accès » des sources de données de la base de données.
* Les anciennes versions du système d'exploitation Windows (par exemple, Windows 7 et Windows 8) désactivent par défaut la collecte de l'attribut « last accessed time » car cela peut impacter les performances du système. Lorsque cet attribut n'est pas collecté, les analyses de NetApp Data Classification basées sur « last accessed time » seront impactées. Vous pouvez activer la collecte de l'attribut last accessed time sur ces anciens systèmes Windows si nécessaire.


====


[[last-accessed-time]]
== Dernière consultation

Lorsque NetApp Data Classification extrait des données à partir de partages de fichiers, le système d'exploitation considère cela comme un événement d'accès et met à jour la « dernière date d'accès » en conséquence. Après l'analyse, NetApp Data Classification tente de rétablir la dernière date d'accès à l'horodatage d'origine. Si NetApp Data Classification ne dispose pas des autorisations d'écriture sur les attributs dans CIFS ou des autorisations d'écriture dans NFS, le système ne peut pas rétablir la dernière date d'accès à l'horodatage d'origine.

Par défaut, NetApp Data Classification n'analyse pas les fichiers lorsqu'elle ne dispose pas des autorisations d'écriture nécessaires pour restaurer l'horodatage d'origine. Si vos données peuvent tolérer que la date du dernier accès ne soit pas réinitialisée à l'horodatage d'origine, activez l'option *Analyser sans autorisations d'écriture* sur la page de configuration du système.

image:screenshot_scan_missing_permissions.png["Capture d'écran montrant l'option permettant à NetApp Data Classification d'analyser vos fichiers même si elle ne dispose pas des autorisations nécessaires pour rétablir l'horodatage d'origine de la dernière consultation."]

Cette fonctionnalité s’applique aux systèmes ONTAP sur site, à Cloud Volumes ONTAP, à Azure NetApp Files, à Amazon FSx for NetApp ONTAP et aux partages de fichiers tiers.


NOTE: Les volumes ONTAP configurés avec SnapLock ont des autorisations en lecture seule et ne peuvent pas non plus rétablir la dernière date d'accès à l'horodatage d'origine.
